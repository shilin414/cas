## 2. Go 后端环境

### 2.1 Go 版本与 Toolchain

- **Go 版本**：`1.27`
- **toolchain 版本**：未声明 `toolchain`，只能确认 Go 1.27 系列。
- **精确补丁版本**：需要 Jenkins 管理员固定。

### 2.2 main 包路径

| 角色 | main 包路径 | 用途 |
| -- | -- | -- |
| API | `./cmd/api` | REST 短请求控制面 |
| Stream | `./cmd/stream` | SSE 长连接面 |
| Worker | `./cmd/worker` | Provider 执行与飞书投递 |
| Scheduler | `./cmd/scheduler` | 定时任务与目录同步 |
| Migration | `./cmd/migrate` | 数据库迁移后退出 |
| Invariant Checker | `./cmd/invariant-checker` | 可选运维检查与 Metrics |

Worker 必须运行两个独立实例：

```text
studio-worker --provider=feishu_aily
studio-worker --provider=feishu_delivery
```

证据：`backend-go/README.md:19-22,35-40`；`cmd/worker/main.go:30-32,100-135`。

### 2.3 生产构建命令与二进制


当前 `Makefile` 的 `go build ./...` 只用于构建检查，不会形成完整发布产物，见 `backend-go/Makefile:21-22`。

### 2.5 端口与健康检查

| 进程 | 默认端口 | 健康接口 |
| -- | -- | -- |
| API | `8080` | `/health/live`、`/health/ready`、`/metrics` |
| Stream | `8081` | `/health/live`、`/health/ready`、`/metrics` |
| Worker | 无 | 未提供原生 HTTP Probe |
| Scheduler | 无 | 未提供原生 HTTP Probe |
| Frontend Nginx | `80` | 可由 Nginx 静态首页或自定义 health location 检查 |

`/health/ready` 会真实 Ping MySQL 和 Redis，见 `server.go:227-239`。

Startup 没有独立路径，可复用 `/health/live`。

### 2.6 SIGTERM 与优雅关闭

- API/Stream 捕获 SIGTERM，执行 20 秒 HTTP Shutdown。
- Worker/Scheduler 使用 `signal.NotifyContext` 并等待后台任务退出。

建议：

```yaml
terminationGracePeriodSeconds: 30
```

Worker 是否需要更长时间，应结合 Provider 请求超时和 Lease 行为验证。

### 2.7 推荐编译和运行镜像

- **编译镜像**：`golang:1.27-bookworm`
- **运行镜像**：`debian:bookworm-slim`

运行镜像应安装：

- `ca-certificates`
- `tzdata`

暂不优先推荐 Alpine，因为 CGO/musl 兼容尚未验证。Distroless 可在确认纯 Go、CA、tzdata 和诊断策略后再采用。

### 2.8 运行时文件

| 文件/资源 | 用途 |
| -- | -- |
| 角色二进制 | API、Stream、Worker、Scheduler、Migrate |
| `deployment.json` 或 `APP_BASE_PATH` | 前后端统一 base path |
| `db/migrations` | `studio-migrate` 运行时读取 |
| 系统 CA | 外部 HTTPS 连接 |
| IANA tzdata | Scheduler 时区解析 |
| `STORAGE_LOCAL_ROOT` | LocalFS 上传、头像、附件和产物 |

未发现 Go `embed`、运行时模板或字典文件依赖。

### 2.9 可写目录与持久化

默认 `STORAGE_DRIVER=localfs`，LocalFS 会创建目录、临时文件、写入、rename 和删除对象，见 `storage/storage.go:63-105`。

生产建议优先使用 S3/MinIO。如果保留 LocalFS：

- 挂载 PVC 到 `STORAGE_LOCAL_ROOT`；
- 多副本共享时需要 RWX；
- 明确备份、容量、清理和灾备策略。

### 2.10 私有 Go Module

未发现私有 Go Module、`replace` 指令或内部 Git 域名依赖。当前无项目证据要求 `GOPRIVATE` 或私有 Git 凭证。

`Makefile` 仅记录开发机曾使用 `GOPROXY=https://goproxy.cn`，公司 Jenkins 的内部 GOPROXY 需要管理员确认。

## 3. React 前端环境

### 3.1 项目类型与版本

- **项目类型**：Vite React SPA。
- **React 声明版本**：`^18.2.0`。
- **React 锁定版本**：`18.3.1`。
- **不是** Create React App、Next.js SSR 或 Next.js 静态导出。

证据：`frontend/package.json:6-20,22-54`、`frontend/package-lock.json:6827-6846`、`frontend/vite.config.ts:12-46`。

### 3.2 Node.js 版本

项目没有 `engines`、`.nvmrc` 或 `.node-version`。

| 来源 | Node 版本 |
| -- | -- |
| GitHub CI | 22 |
| Frontend Dockerfile | 24 Alpine |
| Vite 最低要求 | `^20.19.0 || >=22.12.0` |

建议 Jenkins 与 Docker 统一使用 Node 24；如果公司只提供 Node 22，应确保至少为 22.12，并同步统一 CI 和镜像约定。

### 3.3 包管理器、安装和构建

- **包管理器**：npm。
- **锁文件**：`frontend/package-lock.json`，lockfileVersion 3。
- **确定性安装命令**：`npm ci`。

```bash
cd frontend
npm ci
npm run typecheck
npm run lint
npm run test -- --run
npm run test:deployment
npm run test:ocr-deployment
npm run check:tokens
npm run build
```

`npm run build` 包含 OCR runtime/resource 准备、TypeScript 编译、Vite 构建和 Nginx 配置生成。

### 3.4 构建输出与运行模式

- **输出目录**：`frontend/dist`。
- **运行模式**：Nginx 静态部署。
- **生产容器不需要 Node.js 进程**。
- Dockerfile 将静态文件放入 `/usr/share/nginx/html/<basePath>/`。

### 3.5 API、SSE 与 WebSocket

- 默认 API：`<BASE_URL>/api`。
- 当前 API base path：`/xiaoan-platform/api`。
- 构建期高级覆盖：`VITE_API_BASE_URL`。
- SSE：`/xiaoan-platform/api/v2/runs/{id}/stream`。
- WebSocket：`/xiaoan-platform/ws`。

SSE 要求关闭代理缓冲和缓存，并保留长连接；WebSocket 要求 Upgrade/Connection header。

### 3.6 Router 与 History Fallback

React Router 使用：

```typescript
basename: import.meta.env.BASE_URL
```

Nginx 生成配置包含 SPA history fallback：

```nginx
try_files $uri $uri/ /xiaoan-platform/index.html;
```

`assets/` 和 `ocr-assets/` 不回退 HTML，不存在时返回 404。

### 3.7 Higress 子路径部署

当前项目已按子路径设计：

- Vite base path 来自 `deployment.json`；
- React Router basename 使用相同路径；
- API、SSE、WebSocket 都使用相同前缀；
- 后端 PublicBaseURL、Cookie path 和 OAuth callback 使用相同 base path。

推荐流量链路：

```text
Higress
  /xiaoan-platform/*（保留前缀）
          ↓
xiaoan-platform-web:80
          ↓
Nginx 静态文件
Nginx /api    → Service api:8080
Nginx /stream → Service stream:8081
Nginx /ws     → Service api:8080
```

Higress 不应在进入前端 Nginx 前剥离 `/xiaoan-platform/`。否则静态资源、Router basename、Nginx location 和 API 路由会失配。

生成的 Nginx upstream 固定为 `api` 和 `stream`。可以保留完整 Deployment 名，同时创建短 Service 名：

- `api` → `xiaoan-platform-api`
- `stream` → `xiaoan-platform-stream`

`PUBLIC_ORIGIN` 必须设置为 Higress 最终 HTTPS Origin，不包含 path；`TRUSTED_PROXY_CIDRS` 必须包含实际 Higress/网关来源网段。

### 3.8 前端构建网络要求

OCR 构建脚本会在缓存不存在时从固定上游下载资源，并校验大小和 SHA-256。Jenkins 必须能访问 npm registry 和 OCR 上游，或者由管理员提供经过校验的离线缓存。

`package-lock.json` 同时引用 `registry.npmjs.org` 和 `registry.npmmirror.com`，企业 npm registry 策略需要确认。

### 3.9 推荐前端镜像

- **编译镜像**：`node:24-alpine`
- **运行镜像**：`nginx:1.27-alpine`

对应公司 Harbor 建议地址：

```text
harbor.hengan.com:8086/lib/node:24-alpine
harbor.hengan.com:8086/lib/nginx:1.27-alpine
```
