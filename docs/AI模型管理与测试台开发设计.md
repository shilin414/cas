# AI 模型管理与测试台开发设计

日期：2026-09-21
版本：v0.1
状态：原始需求设计基线；首期实现及验证边界见同目录 `ai-models-implementation.md`。
适用系统：小安工作助手 Workbench / xiaoan-platform。
编制时范围：仅开发设计。后续已在独立 `model` 分支实施基础模块与测试台，正式业务接入仍未启用。

> 核心目标：统一管理远程模型和浏览器端轻量模型，提供可真实验证的对话、多模态与 OCR 测试能力，为后续智能体路由、自动化判断和应用 AI 能力打基础。
>
> 最重要的边界：统一管理不等于统一在服务器推理；浏览器端 OCR 图片默认不上传；飞书 APP 内兼容性必须经过真机验证。

## 1. 文档使用方式与决策状态

本文区分三类内容：

- **确定需求**：来自本轮用户讨论，作为需求基线。
- **设计建议**：推荐的菜单、架构、对象、接口和开发顺序，评审后才能转成正式实现契约。
- **待验证 / 待决策**：具体模型服务、发布版本、设备兼容性、资源体积、性能门槛等；不能当作已交付或已确认事实。

本文中的路由、权限码、表名和目录名均为新增设计建议，不表示仓库已经存在。实际开发以审定后的 OpenAPI、迁移和测试为准。

### 1.1 确定需求

| 编号 | 需求 | 本期边界 |
|---|---|---|
| R01 | 统一配置模型，供未来多个业务复用 | 建设公共模型基础能力，不分别在业务里保存连接和密钥 |
| R02 | 配套真实对话测试 | 支持多轮文字问答，不以简单连通性检测代替 |
| R03 | 图片、视频、PDF 等多模态测试 | 在受支持的连接与模型上完成真实发送、理解和追问 |
| R04 | 纳入浏览器端轻量模型 | 首个候选为 PP-OCRv6 Tiny，不局限于远程大模型 |
| R05 | 识别标签上的 20 位数字码 | OCR 为主，不将黑白条码解码作为必须前置步骤 |
| R06 | 关注飞书 APP 内置浏览器 | Android 和 iOS 分别验证，不预先承诺全部兼容 |
| R07 | 暂不开发后续业务场景 | 路由、智能推送、应用增强、实际数字码查询接入均延后 |

### 1.2 推荐结论

1. 模块名称采用 **AI 模型管理**，覆盖远程模型与端侧模型。
2. 管理入口放在 **企业管理 → 平台管理 → AI 模型管理**，不新增面向普通用户的一级菜单。
3. 后端逻辑独立成模块，首期不拆独立微服务。
4. 提供一个模型测试台，根据能力切换为对话测试或 OCR 测试。
5. 首期建设完整测试闭环，而不是只有配置表和“测试连接”按钮。
6. 先完成飞书端 OCR 最小验证，再决定该端侧方案的发布范围。

## 2. 当前系统与本模块的关系

本节为 2026-09-21 的仓库检查结论，不是新功能描述。

- 当前主架构为 React 前端、Go 后端、MySQL 5.7 和 Redis。
- `backend-go/api/openapi.yaml` 是 HTTP 契约来源；数据库查询使用 sqlc。
- 企业管理已有资源管理、权限管理、组织架构和平台管理。
- 平台管理已有 Provider 和审计日志入口。
- 现有 Provider 页面展示已注册运行时能力，不是通用模型配置页面。
- 后端已有加密和存储基础设施，但不能未经评审直接复用原有飞书 token 密钥用途或附件授权规则。

### 2.1 与执行 Provider 的边界

| 对象 | 职责 | 不承担的职责 |
|---|---|---|
| 现有执行 Provider / Runtime | 驱动智能体或应用任务执行 | 不自动成为通用模型连接库 |
| 远程模型连接 | 描述协议、地址、认证和调用限制 | 不代表一个智能体，也不包含业务路由策略 |
| 模型配置 | 描述可调用模型、能力与默认参数 | 不决定用户是否有权执行某项业务 |
| 端侧模型资源版本 | 描述浏览器推理所需资源与适配器 | 不允许管理员注入任意可执行脚本 |
| 未来场景绑定 | 指定某业务场景使用何种模型和参数 | 不在本期建设完整场景引擎 |

新增模型模块不会自动改变现有 Aily 智能体使用的模型，也不替换现有 Task / Run / Artifact 主链路。

以下路径相对于仓库根目录，供开发定位：

## 3. 范围与非目标

### 3.1 本期范围

- 远程模型连接的新增、编辑、启停与凭据维护。
- 模型配置管理、能力声明、验证状态和引用保护。
- 多轮对话测试，覆盖文字、图片、视频、PDF 的明确能力分支。
- 支持能力内的流式响应、停止请求、错误诊断与调用元数据。
- 统一远程调用入口，测试台与未来业务复用同一实现。
- 浏览器模型受控资源配置与版本管理。
- OCR 测试台及“20 位数字码”预设。
- 飞书 Android / iOS 真机验证与发布兼容矩阵。
- 基础 RBAC、密钥保护、上传保护、审计与清理策略。

**多模态验收口径：** 所有要求的输入类型都要在测试台有明确的能力表达；不能宣称所有模型支持所有类型。完成“多模态测试交付”前，文字、图片、视频、PDF 必须分别至少有一条已选定、已适配、已真实验证的处理路径。可以来自不同连接。若缺少某类服务或处理方案，该项标记为阻塞/未交付，不得用“能上传但不能推理”关闭需求。

### 3.2 本期不做

- 智能体自动路由、自动化智能推送策略及应用业务改造。
- 把 OCR 结果接入正式数字码查询业务；本期只验证识别与确认环节。
- 实时摄像头连续扫描、批量扫码、黑白条码解码专用模块。
- OCR 模型训练、微调和通用模型转换平台。
- 任意上传 ONNX 就可运行的开放平台、任意远程 JS 插件加载。
- 模型市场、复杂负载均衡、自动跨模型切换、完整计费系统。
- 知识库、向量检索、完整提示词管理平台。
- 全套 PDF OCR、视频抽帧、音频转写流水线默认一次性建设。

辅助解析并非一律排除：只有当某个首期必测输入需要该路径、且方案明确获批时，才实现相应最小处理器；必须显式标记，不冒充模型原生能力。

## 4. 信息架构与页面设计

```text
企业管理
└─ 平台管理
   ├─ AI 模型管理
   │  ├─ 模型列表
   │  ├─ 连接与资源配置
   │  └─ 模型测试台
   │     ├─ 对话 / 多模态测试
   │     └─ OCR / 20 位数字码测试
   ├─ Provider（现有执行运行时）
   └─ 审计日志
```

建议路由：`/enterprise/ai-models`，内部使用列表、连接、资源和测试子页。桌面与移动端共用模型、权限和状态逻辑，分别安排布局；不在移动端压缩照搬三栏桌面 UI。

### 4.1 模型列表

建议列：名称、能力类型、运行位置、连接/资源版本、启用状态、验证状态、最后测试时间、操作。

操作：新增、编辑、开始测试、启停、查看调用记录、查看引用、删除未使用配置。

- “启用”与“已验证”分开表示；验证成功不自动启用，启用也不代表兼容性已验证。
- 模型地址、协议、能力、资源版本等实质配置改变后，相应旧验证结果标记失效。
- 点击“开始测试”携带稳定模型配置 ID，不通过显示名定位模型。
- 不预建未实现的场景绑定、模型评测等空页面。

### 4.2 对话测试布局

桌面：对话区 + 参数/诊断侧栏。移动端：对话区为主，参数和详情进入抽屉。

- 顶部：模型选择、运行位置、能力提示、新建对话。
- 中部：用户消息、附件预览、模型回复、明确错误。
- 底部：文字输入、添加图片/视频/PDF、发送、停止。
- 参数：系统提示词、该连接支持的输出限制及采样参数。
- 详情：实际模型、配置版本、耗时、上游用量、处理方式、请求标识和取消状态。

### 4.3 OCR 测试布局

- 上传/拍照、方向修正、裁剪和手动框选。
- 原图与文字框，可放大对照。
- 原始 OCR 文本、每行识别分数与编号候选。
- 20 位格式检查、可编辑候选、人工确认按钮。
- 模型资源版本、设备摘要、实际运行后端、缓存命中、加载与推理耗时。
- 不要求 OCR 模型支持聊天；测试类型由能力决定。

## 5. 领域对象与状态

### 5.1 模型分类采用两个维度

- `capability_kind`：首期至少区分 `chat` 与 `ocr`；图片/视频/PDF 输入等作为细分能力。
- `execution_location`：`server_remote` 或 `browser_local`。

不使用“大模型=远程、小模型=本地”的硬编码分类。UI 可显示易懂标签，内部使用稳定枚举。

### 5.2 远程连接

建议字段：ID、名称、适配器类型、服务地址、密钥引用、启用状态、超时、并发限制、创建/更新时间、配置版本。

一个连接可被多个模型配置引用；不为每个模型复制同一份密钥。协议兼容声明不等于图片、视频、PDF 的行为也完全兼容，必须由适配器和实测能力决定。

### 5.3 模型配置

建议字段：稳定 ID、显示名、上游模型标识、能力类型、运行位置、连接 ID 或端侧资源版本 ID、能力声明、默认参数、启用状态、配置版本。

不变量：

1. 远程模型必须引用连接；端侧模型必须引用受控资源版本，两者互斥。
2. 调用时取一次不可变配置快照，记录版本，避免一条请求中途混用新旧配置。
3. 用户可设置参数必须经过适配器白名单与范围校验；不直接转发任意参数 JSON。
4. 有引用的连接/模型/资源不能硬删除；首期优先禁用/归档。
5. 已禁用配置不能启动新调用；禁用不虚假宣称已经撤回正在执行的上游请求。
6. 首期不提供跨远程/端侧类型的“万能默认模型”。业务场景选择留到后续。

### 5.4 能力声明与验证记录

能力至少包括：文本输入、图片输入、视频输入、PDF 输入、流式输出、结构化输出，以及每类输入的限制与处理方式。

验证状态建议采用 `unverified / passed / failed / unsupported`，并附测试时间、配置版本、适配器版本与设备/环境。失败是一次测试结果，不一定意味着永久不支持。

有效能力取“适配器实现能力 ∩ 模型声明 ∩ 部署限制”。管理员勾选“支持视频”不能让不支持的适配器突然具备视频处理能力。

### 5.5 浏览器模型资源版本

一个可用 OCR 配置引用一个完整资源清单，而不是只存一个模型 URL。

资源清单建议包括：

- 适配器名称、版本、SDK/运行时版本及可重现构建标识。
- 检测/识别模型、字典、预处理配置，以及运行时必需资源。
- 每个文件的受控地址、字节大小、完整性校验值、用途。
- 来源、许可信息、资源审核状态与验证证据。
- 缓存版本键、支持能力、已测设备范围。

资源版本发布后不可原地替换同一 URL 的内容。升级生成新版本，回滚重新指向旧版本；禁止混用不同版本文件。

状态建议：`draft → validated → enabled → disabled/archived`；未通过资源完整性和最小运行验证的版本不得标记为可用。

## 6. 对话与多模态行为契约

### 6.1 消息结构

消息由角色和内容片段组成。内容片段包括文本、图片附件引用、视频附件引用和 PDF 附件引用。

附件引用必须带归属、类型、大小与生命周期状态；前端只传系统附件 ID，不允许借测试接口任意传服务器本地路径或任意待抓取网址。

服务端负责组装真正发送给上游的请求，校验会话归属、模型权限、附件归属、配置版本及能力限制。

### 6.2 输入处理模式

| 输入 | 原生模式 | 辅助模式（仅显式实现时） | 必须展示的信息 |
|---|---|---|---|
| 文字 | 文本消息 | 无 | 是否发生历史截断 |
| 图片 | 图像内容按协议发送 | 经批准的缩放/格式转换 | 实际图片尺寸与转换 |
| PDF | 按服务支持的文件输入方式发送 | 提取文本、按页转图或 OCR | 页范围、处理方式、遗漏/截断 |
| 视频 | 按服务支持的视频输入方式发送 | 按策略抽帧，音轨另行处理 | 帧时间点、是否包含音频、处理范围 |

- 不支持时应在发送前阻止，并返回明确错误；禁止只发送文件名、丢掉附件后伪装成功。
- 模型不支持某种输入时，不自动跨模型路由。
- 不静默把“原始 PDF”换成“提取后的文字”，或把“视频”换成“几张图”。
- 辅助处理派生物继承原附件的归属与清理策略，记录处理器版本。
- 模型给出的页码、时间点属于待核验的模型输出，不标为已经验证的事实。

### 6.3 多轮上下文

- 首期建议同一测试对话固定模型；切换模型默认新建对话。
- 后续追问携带适配器所需的历史及附件上下文，不能只在第一轮发送附件。
- 上游文件句柄按连接/会话隔离，不跨用户、跨连接复用。
- 上下文或附件超限时提示；截断策略必须可见，优先阻止静默丢失必要附件。
- 文件过期后不假装仍有完整上下文，提示重新上传或开启新对话。
- 中断回复默认不作为完整助手回答进入下一轮；是否保留部分回复由 UI 明确说明。

### 6.4 流式、停止与重试

每次调用有稳定 `invocation_id`。状态建议为：`queued → running → succeeded / failed / cancelled / indeterminate`。

- 上游尚未提交的取消可确定标记 `cancelled`。
- 已提交时先记录取消请求；上游是否真正停止、是否仍计费用独立字段表示。
- `indeterminate` 表示请求可能已被上游接收，但终态未知；不能冒充成功、失败或取消成功。
- 关闭浏览器/SSE 断开不等于上游停止；通过状态接口查询结果。
- 同一提交使用幂等键；重复点击返回同一次调用，不启动两次计费请求。
- 重试是明确的新调用。对于提交确认不明的请求，不默认自动重试。
- 受限重试只有在适配器能证明安全或上游支持幂等时才允许。

建议事件：`started`、`delta`、`usage`、`completed`、`failed`、`cancel_requested`、`cancelled`、`indeterminate`。事件带调用 ID 与顺序标识；终态持久化后才发布终态事件。

## 7. 统一架构与执行边界

```text
                  AI 模型配置 / 权限 / 版本
                            │
             ┌──────────────┴──────────────┐
             ↓                             ↓
       远程调用应用服务                浏览器资源清单
             ↓                             ↓
       受控协议适配器                  浏览器推理适配器
             ↓                             ↓
       远程模型服务                    本地 OCR 推理
             ↑                             ↑
       对话测试台                      OCR 测试台
       后续业务服务                    后续业务页面
```

### 7.1 公共职责

统一模型 ID、能力描述、配置版本、错误分类、调用来源和诊断约定；但聊天流与 OCR 区域结果使用不同的类型结构，不能强塞进同一个字符串响应。

- 对话：消息、输出片段、结束原因、用量。
- OCR：区域坐标、文字、分数、候选编号、耗时和模型版本。

### 7.2 后端远程调用

建议新增 `backend-go/internal/aimodel/` 作为逻辑模块。模型适配差异限制在适配器层，业务层不散落供应商判断。

测试和后续业务共用同一授权、配置解析与远程请求实现，不为测试台另写绕过限制的通道。

建议首期：短时、有限额的测试调用由 API 所在进程执行，记录独立测试调用状态，不进入用户 Task 列表；达到配置的最大时长必须中止或标记终态未知。进程重启后回收悬挂记录，不把记录永久留在运行中。视频等长流程若超出此执行边界，必须另做持久化后台执行设计，不能靠无限拉长请求超时解决。

这不是生产自动化的后台执行保证。未来接入自动化仍必须保留现有 Run、Claim、Outbox 等正确性边界，不能借用测试接口绕过任务授权与幂等机制。

### 7.3 前端浏览器推理

建议新增独立能力层，封装初始化、资源加载、取消、释放和结果规范化。OCR 测试台与后续应用调用同一适配器，不分别复制 SDK 调用。

端侧运行不需要远程 API Key；配置清单响应不得包含后端密钥、对象存储管理凭据或任意执行脚本。

本地推理结果与客户端耗时均属于客户端报告，不作为可信审计、计费或业务授权依据。

## 8. 浏览器 OCR 选型与资源管理

### 8.1 已查证的信息与未验证项

截至 2026-09-21，官方 PaddleOCR.js 文档列出 PP-OCRv6 Tiny 的检测/识别模型名称及 Worker 配置；这是选型依据，不是本项目运行证明。[S1]

PP-OCRv6 文档中的 `1.5M` 指参数规模，不等于整个浏览器下载包 `1.5MB`。[S2] 实际首包必须统计模型、运行时、配置等全部必需资源，不仅统计某个权重文件。

候选组合：`PP-OCRv6_tiny_det` + `PP-OCRv6_tiny_rec`。最终 SDK、资源发布版本、许可可用性、下载体积及手机效果均待验证。不能把文档 main 分支当作已安装且可重现的发布版本。[S1]

### 8.2 首轮验证策略（建议）

- 优先 WASM 单线程；独立 Worker 在目标环境验证通过后启用。
- 不把 WebGPU、多线程或跨源隔离作为首期必备条件。
- 在数字区域裁剪后做识别，一次处理一张；限制解码后像素规模，避免只按文件大小限制。
- SDK/JS/WASM 与模型配置版本锁定，依赖不自动跟随 CDN 最新版。
- 同源或经审核的受控静态地址托管资源；配置遵守当前部署子路径。
- 错误分阶段显示：下载、校验、初始化、图片解码、检测、识别。

官方 ORT 文档说明 `numThreads=1` 关闭多线程；多线程另要求浏览器能力及跨源隔离，JS/WASM 应来自匹配构建。[S3] 独立 Worker 与 WASM 多线程不是同一能力。OCR SDK 宿主还负责资源托管与 Worker 构建环境。[S4]

### 8.3 缓存与生命周期

- 首次进入 OCR 功能才加载，首页不预下载全套模型。
- 展示已知资源大小和分阶段状态；未知进度不显示虚假百分比。
- 按版本缓存，校验成功才标记完整；中断下载不产生可用版本。
- 配置读取与模型资源缓存分开；禁用配置后不再由正常 UI 发起新识别。
- 已经下载到用户设备的模型不能保证被远程收回，不能把缓存当成强 DRM 或安全边界。
- 缓存不可用时允许受控的内存加载或提示重试，不无限循环下载。
- 页面离开、取消和重新选图时释放旧图像、Object URL、Worker/推理实例等资源。
- 禁止旧图片的异步结果覆盖新图片结果；每次识别使用请求序号。
- 模型资源缓存不等于测试图片缓存；图片与识别出的完整编号默认不做持久化缓存。
- 不承诺全应用离线：即使资源已缓存，登录、配置校验和实际编号查询仍可能需要网络。

## 9. 20 位数字码识别规则

### 9.1 场景定义

目标是标签上印刷的 20 位数字字符串，不假设它属于某个行业标准、条码制式或防伪码规则。

本期完成：取图 → 裁剪 → OCR → 候选提取 → 格式检查 → 人工校对确认。确认只展示测试结果，不调用正式查询接口。

### 9.2 固定规则

1. 全链路使用字符串；禁止转为浮点数或整数。前导零必须保留。
2. 候选格式为完整匹配 `^[0-9]{20}$`；不能从 21 位或更长数字串中截取 20 位当作成功。
3. 不自动补零、猜位、截断或让大模型补全。
4. 可清除同一候选内部经位置关系确认的分组空格；不得全图去掉所有非数字后拼接。
5. 分行/分框拼接只在同一选区且布局关系经过验证时允许，保存拼接来源并要求人工确认；首期不确定时直接标记多个候选。
6. `O/0`、`I/1` 等仅作疑似混淆提示，不静默改写。任何允许的字符规范化必须显示前后差异并测试。
7. 同图多个编号分别展示；日期、价格、批号不与候选拼接。
8. 未明确编码规则前，不增加校验位算法；“20 位格式通过”不等于业务有效或真实性验证。
9. OCR 分数不表述为正确率或正确概率，不用单一分数替代人工确认。
10. 首期所有候选均需确认，不因位数正确就自动查询。

### 9.3 建议返回结构

- 原始区域：坐标、原始文字、模型分数。
- 候选：原始文字、整理后的字符串、来源区域、规范化步骤。
- 检查结果：位数、是否纯数字、是否存在歧义或多个候选。
- 人工编辑值：仍按相同规则检查；保留“已人工修改”的本地标记。

模型原始分数与业务规则检查分开，不能发明未经校准的“综合置信度 99%”。

### 9.4 最小回归样例

| 输入/场景 | 期望 |
|---|---|
| `01234567890123456789` | 保留前导零，20 位格式通过，仍需确认 |
| `1234567890123456789` | 19 位，提示位数不符 |
| `123456789012345678901` | 21 位，不截取 |
| `01234 56789 01234 56789` 位于同一数字区域 | 可生成去空格候选，显示处理说明 |
| 数字区域中含 `O` | 非数字/疑似混淆提示，不静默替换 |
| 两个独立 20 位码 | 显示两个候选，用户选择 |
| 编号附近有日期和价格 | 不跨区域拼接 |
| 模糊、反光、遮挡、斜拍 | 提示重拍/裁剪/修改，不伪造完整编号 |
| 先选 A 图后快速选 B 图 | A 的迟到结果不能覆盖 B |

## 10. 飞书 APP 兼容性验证

### 10.1 结论边界

官方 ORT 兼容表列出浏览器与执行后端，但不足以证明飞书特定版本内置浏览器可用。[S5] 本方案未进行飞书真机测试，当前状态必须写为 **待验证**。

不假设飞书所有 Android/iOS 版本具有相同内核行为；桌面浏览器成功也不能替代飞书手机验收。

### 10.2 验证分层

1. **取图**：相册选择、拍照、权限拒绝、取消、方向信息、图片解码。
2. **加载**：HTTPS、实际部署子路径、资源可达、类型响应头、资源完整性。
3. **运行**：WASM 初始化、Worker 可用性、单线程识别、内存压力。
4. **体验**：首次下载、缓存后启动、连续识别、后台切换与返回。
5. **隐私**：检查网络请求，确认本地 OCR 路径不上传原图、裁剪图和完整编号。

如果普通文件选择无法满足飞书实际拍照行为，再单独评估飞书取图能力与所需权限；不在文档中未经验证写死 JSAPI 名称或版本。

### 10.3 最小设备矩阵（建议）

| 环境 | 必测内容 | 初始状态 |
|---|---|---|
| Android 飞书：业务代表性手机 | 取图、首次/缓存加载、OCR、连续操作、网络审计 | 待验证 |
| Android 飞书：较低性能手机 | 同上，重点内存与卡顿 | 待验证 |
| iPhone 飞书：业务代表性手机 | 同上，单独验证 Worker、缓存和图片格式 | 待验证 |
| iPhone 飞书：较旧支持设备 | 同上，重点资源压力 | 待验证 |
| 桌面浏览器 | 功能基线与开发回归，不替代手机结论 | 待验证 |

每条证据必须包含手机型号、系统版本、飞书版本、SDK/模型/资源版本、部署版本、网络条件和样本集版本。

不为 OCR 擅自对整个应用增加 COOP/COEP 等响应头；任何修改均需验证现有飞书认证、嵌入和资源加载不回归。

### 10.4 失败与降级

- 不兼容时停止自动初始化重试，清晰说明原因并保留手动输入/修改。
- Worker 失败不静默转入可能卡死页面的主线程方案；只有单独验证通过才开放该退路。
- 本地失败不自动切云端。未来如增加云端 OCR，需明确告知图片将上传，并单独授权。
- 发布说明只覆盖已验证矩阵，不使用“支持所有飞书客户端”的描述。

## 11. 数据与存储设计建议

以下是逻辑实体，可在评审后合并物理表，避免为了统一而建立过度抽象。

| 建议实体/表 | 关键内容 |
|---|---|
| `ai_model_connections` | 协议、地址、密钥引用、限制、状态、版本 |
| `ai_models` | 模型配置、能力、运行位置、连接/资源版本引用 |
| `ai_browser_model_versions` | 不可变资源清单、适配器版本、大小、hash、许可信息 |
| `ai_model_verifications` | 配置版本、输入类型、环境、测试结论与时间 |
| `ai_test_sessions` | 测试会话所有者、固定模型、创建/过期时间 |
| `ai_test_messages` | 角色、内容片段、附件引用、归属与过期时间 |
| `ai_test_attachments` | 私有存储引用、MIME、大小、状态、归属、派生物 |
| `ai_model_invocations` | 调用状态、来源、快照、耗时、用量、错误、取消语义 |

- 遵守现有租户/企业边界；若当前为单企业部署，不凭空改造全站多租户，但所有归属与权限不得依赖客户端自报。
- MySQL 5.7 保存配置和调用真相；Redis 仅作必要的实时、限流和缓存用途。
- 附件字节不放业务表；存储引用由服务端生成，下载按会话归属鉴权。
- 使用显式 SQL 列、正反向迁移和事务，删除约束与引用检查必须处理并发竞争。
- 配置删除不级联清空审计证据；日志保留必要的非敏感快照。
- 首期测试会话按所有者隔离，不提供管理员随意浏览他人提示词与文件的能力。

### 11.1 保存与清理建议

为支持远程多轮对话，测试消息和附件需要短期保存；这与“调用日志默认不存正文”是不同的数据用途。

建议默认值：测试会话/附件保留 24 小时、调用元数据保留 30 天。**这两个数值为待确认建议，不是用户已确定政策。** 开发启动前应确定部署配置、最大值和清理责任。

- 页面明确告知远程测试数据会发送到所选模型服务，以及本系统保留期限。
- 删除会话后立即阻止再访问，异步清理原文件、派生物和本系统控制的上游文件句柄。
- 清理任务可重试、可审计；不能因清理失败把已删除数据重新暴露。
- 不承诺控制第三方服务已经接收内容的保留策略。
- 本地 OCR 图片、结果和完整编号默认仅保留在页面内存；离开页面清理，不套用远程附件上传链路。

## 12. API 与权限契约建议

### 12.1 接口分组

建议管理 API 前缀：`/api/v2/admin/ai-models`。最终路径与错误响应由 OpenAPI 评审确定。

| 方法/资源 | 职责 |
|---|---|
| `GET/POST /connections` | 列表与新增连接，响应不含明文密钥 |
| `GET/PATCH/DELETE /connections/{id}` | 详情、编辑、删除未引用连接；启停作为受控编辑 |
| `PUT /connections/{id}/credential` | 独立替换密钥；空值不隐式清空 |
| `GET/POST /models` | 模型列表与新增 |
| `GET/PATCH/DELETE /models/{id}` | 详情、编辑、启停、引用保护删除 |
| `GET/POST /browser-versions` | 资源版本查询与受控登记，不上传任意脚本 |
| `GET /models/{id}/manifest` | 返回该用户可测试模型的安全端侧清单 |
| `POST /test-sessions` | 创建本人测试会话 |
| `GET/DELETE /test-sessions/{id}` | 查看/清除本人测试会话 |
| `POST /test-sessions/{id}/attachments` | 远程测试附件上传 |
| `GET/DELETE /test-sessions/{id}/attachments/{attachmentId}` | 授权预览与移除未使用附件 |
| `POST /test-sessions/{id}/messages` | 幂等提交远程测试消息，返回调用 ID |
| `GET /invocations/{id}` | 查询本人调用的权威状态 |
| `GET /invocations/{id}/events` | 流式事件，沿用 Cookie 认证边界 |
| `POST /invocations/{id}/cancel` | 请求取消，返回真实可知状态 |
| `GET /invocations` | 按权限查看脱敏调用元数据 |

凭据与资源配置编辑采用版本号/条件更新避免并发覆盖。所有有副作用接口遵守现有 Cookie + CSRF 约束；GET 不触发真实计费测试。

浏览器 OCR 首期没有“上传图片做推理”的 API。若收集非内容性能遥测，应单独声明用途，只报必要元数据，并标记为客户端报告。

### 12.2 权限拆分建议

- `ai.model.read`：查看模型及脱敏配置。
- `ai.model.write`：维护配置、启停和引用保护删除。
- `ai.connection.secret.write`：写入/替换远程密钥，无读取明文能力。
- `ai.model.test`：发起可能产生费用的测试，包括加载受控端侧测试配置。
- `ai.model.log.read`：查看获授权范围内的脱敏调用元数据，不隐含读取他人测试内容。

沿用现有 Admin RBAC 与超级管理员规则；后端独立校验，菜单隐藏不作为授权。未来普通业务用户使用 OCR/AI 通过业务权限，不要求授予企业管理权限；届时新增最小化业务配置解析入口，不能让普通用户直接调用管理员接口。

### 12.3 错误分类

至少区分：未授权、配置禁用、能力不支持、参数不支持、附件无权访问/过期、格式或大小不符、上游认证失败、限流、网络/超时、协议解析失败、取消状态未知、端侧资源校验失败、浏览器不兼容。

错误响应给出稳定错误码、可读说明和请求标识；上游原始响应先脱敏和限长，不直接把 Authorization、文件签名 URL 或提示词拼到错误信息里。

## 13. 安全、隐私与可观测性

### 13.1 远程连接与附件

- 密钥仅服务端解密使用，接口仅返回“已配置”及必要脱敏标识。
- 评审独立加密用途、密钥版本与轮换方案，不直接复用飞书 token 的业务语义。
- 默认禁止任意自定义认证请求头；必要字段走受控协议配置。
- 服务地址限制协议和可访问目标，处理 DNS/重定向导致的 SSRF；内网模型服务须由受信任部署配置显式允许，不提供关闭全部校验的开关。
- 附件限制数量、字节、解码后尺寸/页数/时长及允许 MIME；不要只信扩展名。
- 解析 PDF/视频等不可信文件时隔离处理、限制耗时与资源，禁止 shell 拼接文件名。
- 请求超时、并发、输出量和测试频率均有上限；系统提示词不能关闭这些限制。
- 模型回复按不可信内容渲染，不执行 HTML/脚本、不自动调用工具或打开 URL。

### 13.2 端侧资源与图片

- 模型资源经过受控发布与完整性校验，禁止管理员填入任意可执行代码地址。
- 用户图片与完整编号不得进入错误上报、埋点、截图回放或默认日志。
- 最小验证包括网络抓取证据，而不只检查是否调用了显眼的上传接口。
- 下载模型不等于上传用户图片；UI 清楚区分网络资源加载和数据外发。
- “端侧”也不等于防篡改：未来业务后端仍需校验编号、授权和查询限流。

### 13.3 基础观测字段

建议记录：调用 ID、操作者、测试/业务来源、模型和配置版本、开始/结束时间、状态、错误码、请求排队/总耗时、上游返回用量及可获得的首字耗时。

未返回的用量为未知，不写成 0；成本未配置准确单价与计量规则前不显示为实际账单。OCR 分开记录资源加载、初始化和推理耗时；缓存命中与总下载字节分开。

- 桌面/移动端布局、键盘操作、文件移除和错误提示可读性。

### 14.3 OCR 测试集

真实样本须经用户授权，可包含：清晰标签、前导零、分组空格、换行、斜拍、反光、模糊、遮挡、多个码、日期/价格干扰、低分辨率、大图、不同相机方向与重复取图。

每个样本人工标注完整正确字符串，模型选择/参数调试用样本与最终验收样本分开。测试集版本与许可/使用范围进入报告。

核心指标：

- **整串准确率**：在有效且标注清晰的样本中，首次首选候选与完整 20 位标注完全一致的比例；无候选也计失败。
- **候选覆盖率**：正确整串是否出现在候选列表中；不得拿它替代首选准确率。
- **无效样本误接受率**：不存在合法目标码的样本，却被展示为有效格式候选的比例，单独统计。
- 人工修改率、无结果率、多候选率。
- 冷启动下载/初始化耗时、热启动识别 P50/P95、连续操作崩溃或卡死次数。

指标样本量、目标阈值和支持设备下限在技术验证后由产品/业务共同确认，当前不虚构“99%”或“几百毫秒”的已达成承诺。未批准验收门槛前不得宣布 OCR 可上线。

### 14.4 绝对通过项

这些不依赖性能门槛，首期必须通过：

- 前导零不丢失，19/21 位不截取或补全成 20 位。
- 不跨区域随意拼接，不静默替换易混字符。
- 本地 OCR 路径不上传图片和完整编号。
- 不支持的视频/PDF 不被静默忽略。
- 无授权不能访问他人附件、凭据或测试对话。
- 不声称未确认的上游取消已成功。
- 不把未验证的飞书环境标为支持。

### 15.2 发布与回滚

- 通过独立模块开关及管理员权限灰度，不默认向所有用户展示。
- 数据库迁移、后端契约、前端和模型资源按兼容顺序部署。
- 模型资源升级采用不可变版本，可回退配置指针。
- 回滚先禁用新入口/新调用，再处理仍在运行的调用；不为回滚强制删除审计或文件证据。
- 下线不能撤销用户已下载资源，应在运维说明中明确此限制。

## 16. 后续业务方向（不纳入本期）

### 16.1 智能体路由

先推荐并由用户确认；候选智能体必须先按用户权限过滤。模型不得决定权限或擅自执行任务。

### 16.2 自动化推送判断

比较新旧结果，识别异常、重要变化和待处理事项，输出结构化结论及理由。重要告警仍由确定性规则兜底，模型失败不能等同于“不需要推送”。

### 16.3 应用 AI 能力

自由描述转表单草稿、结果摘要、差异解释、行动建议。业务动作仍需原有授权与必要确认。

### 16.4 20 位数字码查询

页面复用端侧 OCR 能力，用户确认后仅提交编号字符串；查询后端独立校验、鉴权和限流。条码解码可作为未来独立输入路径，不替代数字 OCR。

### 16.5 场景绑定

有第一个真实业务消费者时，再增加“场景 → 模型/资源版本 → 参数”绑定。场景须同时约束能力类型和运行位置，例如后台自动化不能直接依赖用户浏览器推理。
