# AI 模型管理：实现、部署与验证记录

日期：2026-09-21（本机 Asia/Shanghai）
开发分支：`model`；基于 `e24c70a` 的独立工作树。
范围：模型基础设施和测试台，不接入正式智能体路由、智能推送或数字码查询业务。

## 1. 已实现的入口与能力

入口：**企业管理 → 平台管理 → AI 模型管理**。桌面和移动端均接入原有企业管理导航、权限与主题体系。

### 模型与连接管理

- 模型列表、连接管理、测试台、调用记录四个页签。
- 远程连接的新增、编辑、启停、引用保护删除，以及独立授权的密钥设置。
- 远程模型、浏览器本地 OCR 模型的新增、编辑、启停与引用保护。
- 本地模型可导入构建脚本生成的 manifest；导入配置本身不下载 OCR 模型。
- 配置写入与脱敏管理审计同事务提交。审计记录操作者、动作、对象、版本、变更字段名与启停状态，不记录密钥和业务正文。

### 远程对话与多模态测试

- OpenAI Chat 协议：文字、图片；Gemini 原生协议：文字、图片、PDF、视频。
- 多轮历史由服务端保存并带入下一次请求；文件不能只在第一轮可用。
- 同时受适配器、模型能力声明和部署限制约束，不支持的文件明确拒绝，不静默丢弃。
- 支持系统提示词与适配器允许的参数、真实上游流式输出的服务端快照、停止请求、用量与错误详情。
- 界面轮询服务端调用快照，**不是浏览器直连供应商，也不是伪造逐字输出**。本期没有额外的 AI 测试 SSE 端点。
- 服务端返回本人会话的活跃调用 ID，重开标签页后可以恢复查询和停止；本地 sessionStorage 只是辅助。
- 发送回执与历史刷新解耦；历史请求变慢或失败不阻塞停止操作。
- 同一请求的幂等重放不因模型后来停用而重复执行；未知上游结果明确标为 `indeterminate`，不自动重试。

### 浏览器本地 OCR

- 固定适配 PP-OCRv6 Tiny 检测与识别组合，不提供任意脚本/任意模型执行能力。
- 打开系统、打开模型管理、选择本地模型时不加载 OCR 引擎或权重。
- 明确打开 OCR 面板后可选图；点击“开始识别”才加载实际运行资源并初始化。
- 上传/拍照入口、方向处理、旋转、手动裁剪、文字框、模型分数、候选选择与人工修正。
- 20 位数字作为字符串处理，保留前导零；不截取 21 位、不自动补位、不跨区域拼数字、不静默替换 O/0。
- 确认仅在测试页面展示，不调用正式查询接口。
- 模型资源同源、固定版本、大小/SHA-256 校验和版本缓存；不缓存用户图片或完整识别码。
- 取消、卸载和离开测试页签释放本地状态；不会因 Ant Design 保留隐藏页签而留下 OCR 面板。

## 2. 权限与数据边界

权限码：

- `ai.model.read`：读取非敏感模型及连接配置。
- `ai.model.write`：维护模型和连接。
- `ai.connection.secret.write`：独立更新连接密钥，不提供明文回读。
- `ai.model.test`：发起本人测试。
- `ai.model.log.read`：查看本人脱敏调用元数据。

即使是超级管理员，也不能通过测试会话、附件、调用详情接口读取其他用户的测试内容。只有日志权限时不会顺带加载连接、模型或会话正文。

远程测试文件会发送到服务器及所选供应商，调用可能产生供应商费用。浏览器 OCR 路径不上传图片、裁剪结果或完整编号；下载公开模型资源不等于上传图片。

连接密钥使用独立用途派生的 AES-GCM 加密。配置修改可审计，但不提供自动主密钥轮换；更换现有 `TOKEN_ENCRYPTION_KEY` 前，应规划现有会话/凭据处理和重新配置。

远程出网默认要求 HTTPS，并进行 DNS/IP 校验、连接时 IP 固定、不继承代理、不跟随重定向。确需内网或本机服务时，由部署方使用 `AI_MODEL_ALLOWED_HOSTS` 精确允许 host；这也允许该 host 的 HTTP，因此应谨慎限定，禁止配置通配符。

## 3. 数据库与调用生命周期

迁移：`backend-go/db/migrations/0043_ai_models.up.sql` / `.down.sql`。

新增模型连接、模型、本人测试会话/消息/附件、调用状态、配额锁与对象清理记录，复用现有 `audit_logs`。SQL 源查询使用显式列，查询和 API 生成物均由正式工具生成。

关键不变量：

1. 会话准入、请求去重、连接并发名额、用户消息和附件关联在同一事务提交。
2. 准入后读取权威历史，避免漏掉刚提交的上一轮助手回答。
3. 请求准备与执行共同受进程内并发上限保护；附件上传另有有界预处理名额。
4. 关闭运行服务时等待预处理、取消观察器和后台执行分别完成收尾，再关闭数据库。
5. 已发往上游的请求中断，不声称供应商已停止或不会计费。
6. 删除会话先提交不可访问的墓碑，再清理对象；失败保留重试状态，不恢复成部分文件缺失但仍可访问的会话。
7. 删除单附件与持久对象清理记录同事务提交，物理清理失败可继续重试。
8. 一个过期对象清理失败不阻塞整个批次；重试带持久租约和退避。

当前测试会话采用默认 24 小时期限；调用元数据随会话生命周期删除。**独立的 30 天调用归档尚未实现**，不应按早期建议值对外承诺。对象存储故障期间数据不可访问，但物理清理可能延后。

PATCH 保护当前 HTTP 读取至写入窗口内的版本冲突；跨管理员长时间打开表单后的客户端版本协商尚未扩展。

## 4. 部署顺序

1. 合并时先检查迁移编号。其他并行功能分支也可能使用 `0042`；若冲突，统一重排迁移编号并重新验证，不直接覆盖另一份迁移。
2. 按现有部署机制备份并应用数据库迁移。
3. 部署后端，保留原有认证、RBAC、存储与加密配置。不要把测试用本机允许名单复制到生产。
4. 在前端执行标准依赖安装与构建：

```sh
npm ci
npm run build
```

标准构建的 `prebuild` 会准备固定版本运行资源和模型文件，并检查完整性；现有 Dockerfile 的 `npm run build` 同样执行该生命周期。有效缓存可以离线复用，缺失或损坏且无法下载时构建失败，不生成虚假的可用清单。

开发模式 `npm run dev` 只准备运行资源，不自动下载模型；本机要测试 OCR 时执行：

```sh
npm run ocr:prepare
```

5. 发布本次完整 `dist` 和本次生成的 Nginx 配置，不只复制 JavaScript。
6. 使用生成的 `frontend/public/ocr-assets/ppocrv6-tiny-20260921/manifest.json` 创建本地 OCR 模型。
7. 创建远程连接、独立设置密钥，再创建相应模型配置并进行本人测试。

### 静态服务要求

- ORT 配套模块以 `.js` 发布，避免 Nginx 默认 MIME 配置对 `.mjs` 返回非 JavaScript 类型。
- `assets` 与 `ocr-assets` 中缺失的文件返回真实 404，不落入 SPA HTML fallback。
- AI 管理 API 代理允许 21 MiB 整包，给 20 MiB 文件的 multipart 包装留余量；其他 API 仍保持原有 20 MiB 上限。
- 应用支持既有部署子路径；manifest 必须使用当前部署前缀，不能套用其他环境的绝对路径。
- 不为 OCR 自动放宽全站 CSP。若 Worker 响应严格禁止动态 JS 求值，当前 OpenCV 构建不能初始化；见 `ocr-browser-deployment.md`，需要单独安全评审或更换经验证的构建。

详细资源版本、校验值、许可来源、离线构建和 CSP 边界见 `docs/ocr-browser-deployment.md`。

## 5. 验证环境和证据分类

本轮未迁移或写入共享业务数据库。验证使用本机独立 MySQL 5.7.44、独立的 verify/integration 数据库、专用端口与 Redis key prefix。只使用合成用户和合成素材。

| 证据 | 实际覆盖 | 不代表什么 |
|---|---|---|
| Go 单测、SQL mock、真实 MySQL 集成 | CRUD、密文、引用保护、并发/幂等、owner、迁移往返、清理失败恢复、事务审计回滚 | 不代表真实供应商已经调用 |
| 真实 API + MySQL + 本机协议测试桩 | 文字、图片多轮、PDF、浏览器生成的 WebM、取消、错误、日志脱敏 | 测试桩回答不是大模型能力结果 |
| 真实官方 Tiny 模型 | 合成 20 位码整串识别、裁剪、缓存完整性、本地网络边界与取消/卸载 | 不是所有真实标签的准确率统计 |
| 标准干净资源构建 | 没有预置 tar/manifest/runtime 时，构建生成并校验完整资源 | 不替代最终托管服务验证 |
| 真实 Nginx 1.27.5 静态部署 | JavaScript/WASM MIME、缺失资源 404、20 MiB 文件通过代理、真实 OCR 成功 | Windows Nginx 验证不是 Docker 运行测试 |
| 桌面、390px 触屏模拟、暗色页面 | 页面可用、没有水平溢出、原有主题一致 | 不是 Android/iPhone/飞书真机认证 |

本地验证产物保存在 `.run-logs/model/`，该目录不提交：`nginx-report.json`、`api-report.json`、`ui-report.json`、OCR 生产与干净构建报告、构建/测试日志、截图和覆盖率文件。

## 6. 审查修复清单

- 提前限制附件预处理内存并发，补上传名额上限。
- 幂等查找先于可变配置校验，停用后重放仍返回原调用。
- 会话准入后读取多轮历史，消除交错读取竞态。
- 预处理、watcher 与后台调用分别受关闭等待保护。
- 首次读取版本 CAS，防止服务层重读新版本后认可旧 payload。
- 会话墓碑、单附件清理记录、失败继续与退避。
- 配置变更审计同事务，审计失败回滚配置修改。
- 附件 `created_at`、本人会话 `active_invocation_id` 与严格 OpenAPI schema 对齐。
- 历史刷新不阻止取消，新标签可从服务端恢复活跃调用。
- 切换页签卸载 OCR，未使用不加载引擎和模型。
- 生产 `.js` MIME、干净构建资源打包、资源 404 与上传代理边界。

## 7. 尚需部署方确认的事项

- 真实供应商账号、模型标识、实际多模态支持及供应商费用；本轮没有使用真实付费账号验证。
- Android 和 iPhone 上各目标飞书版本的真机兼容、内存和性能。
- 业务真实数字码样本、可接受的整串准确率与响应时间；当前仅有合成样例与规则回归。
- 严格 Worker CSP 环境的适配方案。
- 生产数据保留政策、自动主密钥轮换和独立长周期调用归档。

智能体路由、自动化推送判断、应用 AI 增强和正式数字码查询接入仍按原讨论留到后续，不在此次提交中启用。
## 8. 本轮收尾结果

- 前端完整回归：106 个测试文件、886 项测试通过；定向严格 lint、类型检查与生产构建通过。
- 部署路径/代理回归：22 项通过；OCR 资源构建专项：5 项通过。
- 模型持久化单测与真实 MySQL 5.7.44 集成：通过，覆盖率 85.3%。
- 远程 runtime：通过，覆盖率 83.9%；关闭交接屏障回归连续执行通过。
- 全后端构建与静态检查通过。全包测试中的 delivery/http 临时可执行文件被 Windows 拒绝时，改为在明确的本地验证目录编译并运行对应完整包测试，均通过，未修改安全设置。
- 真实 Nginx 页面验证：OCR 成功、未使用 OCR 时引擎请求为 0、20 MiB 上传通过、缺失资源返回 404。
- 真实页面复测：新标签可从服务端恢复活跃调用；刻意阻塞历史 GET 时取消请求仍发出，测得 0.066 秒；浏览器未记录页面异常。
- Go、TypeScript 与跨层审查的明确问题均已整改并独立复核。QA 脚本开发模式 MIME 漏检也已补齐。
- 未执行本分支 Go race：本轮环境未启用 CGO；未做真实供应商计费调用和飞书真机认证。

后续用户已追加授权：将本分支与 `app`、`exam` 一并合入 `dev` 并部署。集成时必须处理 `app` 与本分支的 `0042` 迁移号重叠；以集成分支最后的编号、验证与部署记录为准。
