## 已确认并修复

| 区域 | 缺陷与影响 | 修复与验证 |
|---|---|---|
| 执行队列 | Redis 消费组丢失后，读取/回收路径持续失败，进程存活却不处理任务 | 重建受影响的消费组并从 `0` 回放；保留 CAS 去重；验证并发创建、其他错误及取消场景 |
| 任务回收 | XAUTOCLAIM 返回空页但仍有下一游标时提前结束，后续可回收任务被漏掉 | 根据结束/停滞游标而非空页决定结束，测试空页跨越与取消 |
| 执行实例隔离 | 旧 attempt 完成/晚到的 slot 绑定可能移除或覆盖新 attempt 的心跳控制 | 对完整 lease ownership 比对后才能修改控制记录；测试 epoch/token/worker 的变化和真实重叠调用 |
| 执行资源释放 | execute 返回后未保证取消子 context，相关后台工作可能残留 | 在所有退出路径取消子 context，不影响父 context 和替代 attempt |
| SSE 终态资源 | 终态后 hub 停读，转发协程可能卡在已满缓冲区，即使上游连接关闭仍无法退出 | 退出上游读取时先取消 context；使用真实转发函数与满缓冲区复现 |
| SSE 空闲回收 | 旧定时器回调在连接重新使用后迟到，可能提前回收新的空闲周期 | 定时器代次标记，过期回调不能修改当前计时器 |
| 附件上传 | `ParseMultipartForm(50MiB)` 只是内存阈值，没有请求上限；超限内容仍读入/落盘，41MiB reader 会截断更大文件 | 两条入口共享解析边界：文件40MiB、图片5MiB、整体请求40MiB+64KiB；超限413、解析内存阈值1MiB、清理临时文件；验证精确边界、未知长度及禁止存储/上游副作用 |
| 聊天历史 | 晚到的历史请求覆盖新 run，重叠请求污染状态或提前清除加载状态 | 请求所有权及会话失效检查；保留首次加载中的旧历史，并检查历史先于发送回执返回时的顺序与去重 |
| 前端流订阅 | 幂等重放重复建立订阅，旧回调可能在会话删除后污染其他会话 | 同一 run 复用订阅；关闭后使回调失去所有权；旧 run 回放/终态事件不得清除新 run 的活动标记 |
| 工作区资产 | 项目切换、重复刷新、迟到的保存完成回调覆盖新项目资产 | 项目身份、请求代次及组件存活检查；验证 A→B→A、卸载与正常保存 |
| 飞书令牌 | 同一用户/app 缓存未命中时并发刷新；轮换令牌保存失败却仍返回成功并缓存 | Redis 跨进程按 key 协调、拿锁后重读缓存/身份、持久化成功后才发布；所有者检查发布和解锁；并发/取消/轮换失败测试 |

## 明确保留的风险与后续建议

1. **调度池边界需单独设计。** 代码审查发现fallback扫描和reclaim可在常规worker池外执行；有扫描时本地并发可能达到配置值+2，但仍受provider slot约束。慢handler也可能延迟同一维护循环的后续清理。本轮不重写冻结执行内核；建议独立做统一执行配额与维护调度设计，并进行隔离数据库负载测试。
2. **认证锁不是完整分布式fencing。** 操作默认30秒、租约60秒、等待可取消；Redis故障时安全拒绝刷新，不再绕过协调直接调用上游。Redis failover、进程超长暂停、不使用锁的OAuth写入仍是边界。上游令牌轮换与MySQL写入不是原子事务，失败可能需要重新登录。迁移Redis Cluster需为Lua的两个key配置相同hash tag。
3. **前端包体较大。** 当前主包约1.52MB（gzip约484KB）；影响冷启动尤其弱网。没有实际用户性能数据，不做未经度量的大规模分包改造；建议后续用真实构建分析和移动弱网测量制定拆分计划。
4. **旧请求主要通过失效检查隔离。** 被替代的前端请求可能仍执行完成，只是不再修改当前页面。若上游负载成为瓶颈，再为对应API补充取消机制。
5. **生产容量未测量。** 没有对真实飞书、共享开发库或生产环境做负载压测；不能据此承诺QPS或最大并发数。修复消除的是已复现的具体缺陷。
