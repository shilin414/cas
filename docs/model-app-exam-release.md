## Redis 测试事故及防复发

合并测试时曾错误地将“独立 key prefix”当作 Redis 隔离。既有 `TestRedisFlushDoesNotIncreaseProviderCapacity` 对原配置逻辑 DB2 执行了整库清理。主线程已向用户披露；用户接受临时数据需要重新生成，并授权继续。

- 该测试没有清理 MySQL 业务库。只读核查时业务迁移仍为 41、无 dirty，任务/投递记录统计不变。
- Redis 原有登录态、缓存、队列、限时快照可能丢失；没有清理前键清单，未声称全部恢复。
- 已删除测试中的整库清理调用，改为清理本次随机 fixture provider 的四个明确队列键。
- 新增 AST 回归禁止集成测试使用 typed/raw 全库清理命令。
- 集成测试入口在连接前要求明确隔离标记且数据库/Redis 为 loopback；使用原远程 Redis 的配置已实证被立即拒绝，没有建立集成测试连接。
- CI 仅在本次 job 自建的 MySQL/Redis 容器上设置隔离标记。

## 本机部署安排

- 后端二进制与私有配置位于独立发布目录；不覆盖测试 `.env.local`，不切换原 app 工作区。
- 沿用原业务数据库、Redis 配置与加密密钥。附件目录解析为原目录的绝对路径，避免因 worktree 改变而丢失历史文件访问。
- 前端发布经过构建的静态文件及同次生成的 Nginx 配置，保留 `/xiaoan-platform/` 前缀。
- 本机地址为 `http://localhost:3030/xiaoan-platform/`；这不是向未指定远程服务器或公网发布。
- 迁移使用独立的 migrate 命令，先备份再应用 0042、0043，不使用会迁移后继续启动的 api `-migrate`。
- API、stream、Aily worker、scheduler、delivery worker 分批启动；启动前只读检查现有待执行、待投递及同步任务。
- 本次不发送验收飞书消息、不修改真实账号资料、不进行真实模型计费测试。

部署备份、进程清单、日志、健康检查与运行结果记录保留在当前工作树的 `.run-logs/`，不提交凭据、业务备份或模型权重。公网可访问地址、飞书回调白名单及真机验收仍需按实际发布环境确认。
