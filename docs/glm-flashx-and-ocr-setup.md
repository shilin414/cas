# GLM-4.6V-FlashX 与内置 OCR：最简配置

日期：2026-09-21

按[人工数据库手册](deployment/database.md)审核并执行0044及以前的待执行迁移后，系统会自动出现两个模型：

- `GLM-4.6V-FlashX`：远程视觉模型，已预填模型名、内网地址、图片能力、温度 `0.1` 和 600 秒超时。
- `内置 OCR（PP-OCRv6 Tiny）`：浏览器本地 OCR，资源版本、路径、大小和 SHA-256 已固定，无需填写 JSON。

## GLM 只需要做两件事

1. 在后端运行环境增加：

   ```env
   AI_MODEL_ALLOWED_HOSTS=192.168.212.121
   ```

   然后重启后端。该地址是 HTTP 内网服务；不加精确白名单时，后端会按安全策略拒绝访问。

2. 打开 **企业管理 → 平台管理 → AI 模型管理 → 连接管理**，找到 `GLM-4.6V-FlashX 内网连接`，点击 **设置密钥**，粘贴 API Key 并保存。

密钥只写入、不可回读，并使用现有加密机制保存。仓库、迁移和前端默认值都不会写死密钥。

完成后到 **测试台** 选择 `GLM-4.6V-FlashX`，可直接发送文字和图片。默认不限制最大输出 token，避免思考内容占满额度后最终答案为空；调用会显式开启该模型的思考模板参数。

## OCR 不需要配置

OCR 已固定为 `PP-OCRv6_tiny_det + PP-OCRv6_tiny_rec`：

1. 正常执行前端生产构建；`prebuild` 会下载并校验固定版本资源。
2. 在 **测试台** 选择 `内置 OCR（PP-OCRv6 Tiny）`。
3. 点击 **开始本地识别**，再上传图片或拍照。

图片只在当前浏览器页面内存中处理，不上传后端。模型资源使用部署基础路径自动展开，所以根路径、`/xiaoan-platform/` 或其他合法子路径部署都不需要改 OCR 配置。

## 常见问题

- **GLM 显示没有密钥**：到连接管理设置密钥。
- **GLM 提示地址不允许**：检查 `AI_MODEL_ALLOWED_HOSTS` 是否精确包含 `192.168.212.121`，并确认后端已重启。
- **OCR 资源下载失败**：重新执行生产构建，确认 `ocr-assets/ppocrv6-tiny-20260921/` 随静态文件发布。
- **不要把 API Key 填到模型标识、服务地址或 OCR 配置里**。
